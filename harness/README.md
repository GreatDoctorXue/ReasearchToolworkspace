# 可选模型执行指南

仅在环境缺少执行约定、需要仓库提供流程，或用户明确选择仓库流程时加载本页。
已有 Harness / Loop 的 Agent 直接从 [工具目录](../tools/README.md) 读取所选工具指南，采用宿主的执行循环、重试、状态管理和结束条件。
这套约定适用于能读取仓库文件的模型。Python、网络、文件操作与视觉能力由模型所在的平台提供。

## 工具入口

使用 [工具目录](../tools/README.md) 选择能力，再加载对应操作指南与完整规则。

## 执行流程

每次执行一个可验证的动作，观察结果后决定下一个动作，持续循环。

```text
读取目标与当前进度 → 选择工具与下一步动作 → 执行 → 观察输出 → 验证
                                   ↑                      │
                                   └── 根据结果调整后继续 ──┘
```

循环由当前模型所在的 Agent 运行环境驱动。下列步骤约定每次迭代所需的上下文和完成条件。

1. 明确用户的主题、目标产物与现有资料。用户提供已有任务目录时先检查现有进度，根据该任务的实际状态继续。
2. 读取工具操作指南，检查所需能力与依赖。在 `runs/<课题名>/TASK.md` 记录目标、路径和当前步骤。
3. 按工具规则执行，每个阶段记录实际命令、输出文件、成功或失败状态以及恢复方式。
4. 运行相关验证命令，检查产物内容。报告引用需回到来源页码，PPT 需按引擎要求检查版式和内容。
5. 更新任务状态，交付产物路径与验证结果，说明仍需处理的事项。

验证失败时记录失败位置，依据错误调整参数、输入或执行步骤，再验证。保持已有成功产物可用。
满足用户目标且相关验证通过时结束。需要用户输入或外部能力才能继续时，保存进度并说明具体阻塞。
用户要求停止时保存当前进度并结束。相同动作持续产生相同失败时，先检查失败原因并改变恢复方式。

## 任务记录与续跑

新任务在 `runs/<课题名>/TASK.md` 使用下列模板。填写真实执行结果，尚未执行的步骤写为待执行。
同一课题的资料库、环境检查结果和报告都位于该任务目录。`runs/` 已被 Git 忽略，跨机器续跑需要另行转移任务目录。

```markdown
# 任务名称

- 用户目标与交付物
- 采用工具与规则文件路径
- 仓库版本与任务目录绝对路径
- 运行环境与所需能力
- 当前状态（进行中 / 等待输入 / 完成）

## 执行记录

| 步骤 | 状态 | 实际命令或动作 | 输出路径与验证结果 |
| --- | --- | --- | --- |

## 证据与缺口

记录来源、获取失败、未验证信息和能力限制。

## 下一步

写清恢复时要执行的第一个动作，以及该动作需要的输入。
```

恢复任务时先核对记录与实际文件。查询已有库前确认索引存在，继续写报告前读取现有成稿。
遇到同名产物时检查内容并保留用户已有编辑，再判断是否重新生成。

## 能力不足时

| 环境情况 | 执行动作 |
| --- | --- |
| 可以读写文件、执行 Python 并联网 | 按工具指南运行，记录真实结果 |
| 能执行 Python，网络受限 | 处理已提供的本地资料，登记联网步骤与获取缺口 |
| 无视觉能力且扫描件缺少文本层 | 检查是否有可用 OCR，仍无法解析时登记具体文件与页码 |
| 只能对话或读取附件 | 输出基于已读材料的内容，列出需要执行环境完成的命令和未验证产物 |
